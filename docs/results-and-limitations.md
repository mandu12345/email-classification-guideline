# 결과와 한계

## 결과

1. 기존 분류표를 합성 업무 이메일에 적용하면서 **요청과 회신의 혼동** 및 **전문 주제와 공통 행위의 혼동**을 확인했습니다.
2. `일반 행정`을 없애고 공통 4유형을 구성했습니다: `공지 전달`, `자료 요청`, `자료 제공·제출`, `검토·수정 요청`.
3. 각 공통 유형에 **포함/제외 기준**을 정하고, 현재 행위 → 전문 유형 → 공통 유형 → 보류의 **판단 순서**를 문서화했습니다.
4. 가장 가까운 유형에 억지로 넣지 않도록 **범위 밖 / 맥락 부족 / 복합 의도 / 기준 경합**의 4가지 보류 사유를 정의했습니다.
5. 이전 판단, 재검토 후 판단, 수정 사유와 **해결되지 않은 경계**를 별도로 남겼습니다.

결과물은 [이메일 분류 가이드 v1.0](classification-guide-v1.0.md)입니다.

## 이 결과로 **주장할 수 없는 것**

- **합성 이메일 52건**은 실제 업무 이메일의 표현·빈도·복잡성을 대표하지 않습니다.
- 분류 기준을 바꾼 사례를 재검토했으므로 **독립적인 전후 정확도 평가**가 아닙니다.
- **1인 판단 및 AI 검토 의견**을 활용했고, 독립 정답 라벨과 작업자 간 일치도는 검증하지 않았습니다.
- 전문 유형 26개 전체의 정의를 다시 검증한 것은 아닙니다. 일부 사례는 여전히 경계가 불분명합니다.
- 내부 보고·협조 요청을 삭제해 일부 이메일은 범위 밖으로 남습니다. 모든 회신을 분류하는 완성된 체계가 아닙니다.
- 실제 서비스, 자동 답장 로직, 템플릿 품질, 모델 학습·평가·정확도는 **수정하거나 검증하지 않았습니다**.

따라서 최종적으로 말할 수 있는 결과는 **“합성 업무 이메일을 직접 검토해 분류 기준의 결함을 발견하고, 판단 기준·보류 절차·지원 범위를 명시했다”**는 것입니다.

## 이후 검토할 과제

이 항목은 수행한 성과가 아닌 **후속 과제**입니다.

- 실제 업무 메일을 다룰 수 있는 승인된 환경에서 현실적인 사례로 기준 적용성 확인
- 여러 작업자가 동일 기준으로 판단하는지 확인
- `시스템 오류 보고`와 사후 자료 제출 등 미해결 경계 재검토
- 분류 범위가 변경됐을 때 템플릿 연결 및 온보딩에 미치는 영향 별도 분석
