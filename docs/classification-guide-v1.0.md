# 이메일 분류 가이드 v1.0

> 대상: 수신 이메일 **한 통**. 제목과 **현재 본문에 명시된 내용**을 근거로 판단합니다.

## 1. 수정된 분류 구조

| 구분 | v1.0 |
| --- | --- |
| 전문 도메인 | 영업, 마케팅/PR, 인사, 재무/회계, 고객지원, IT/운영 |
| 전문 유형 | 원본 26개 유형 유지 ([원본 표](original-taxonomy.md) 참고) |
| 삭제 | 일반 행정 도메인, 내부 보고·협조 요청 유형 |
| 공통 유형 | 공지 전달, 자료 요청, 자료 제공·제출, 검토·수정 요청 |
| 전체 | **6개 전문 도메인 · 26개 전문 유형 + 공통 4유형 = 30개 유형** |

**공통**은 새로운 전문 도메인이 아닙니다. 여러 업무 분야에서 선택할 수 있는 업무 행위의 묶음입니다.

## 2. 입력·출력과 해석 원칙

- **분류 단위:** 수신 이메일 한 통
- **판단 근거:** 제목과 현재 본문에 명시된 내용
- **기본 출력:** 주 유형 하나. 부 의도는 메모로 기록
- 첨부파일의 존재와 설명은 활용하되 **첨부 내용이 주어지지 않았다면 추정하지 않음**
- `RE:`·`FW:` 또는 이전 요청 제목만으로 분류하지 않음
- 여러 의도의 우선순위를 판단하기 어렵다면 **보류**

## 3. 공통 유형 정의

| 유형 | 포함 기준 | 제외·주의 기준 |
| --- | --- | --- |
| **공지 전달** | 일정·정책·행사·운영 변경을 알리는 것이 중심. 참여 방법이나 준수 안내를 포함할 수 있음 | 다수 수신·선택적 참여 여부만으로 판단하지 않음. 개별 처리 결과 통보나 모든 행동 지시를 자동 포함하지 않음 |
| **자료 요청** | 문서·명단·증빙·정보처럼 식별 가능한 자료의 전달·제출을 요구 | 실물 반납·작업 수행·단순 열람은 제외. 정중하거나 조건부 표현이어도 구체적 요구라면 검토 |
| **자료 제공·제출** | 문서·파일·계정 정보 등 식별 가능한 자료를 제공하거나 제출하는 것이 중심 | 단순 완료 보고·거절·처리 결과 통보를 자동 포함하지 않음 |
| **검토·수정 요청** | 기존 문서·표현·결과물에 대한 의견·확인 결과 회신이나 명확한 수정 요구 | 관례적인 추가 의견 문구만으로 선택하지 않음. 승인·등록·반납 같은 일반 처리 요청은 제외 |

**보충 규칙**

- 첨부파일 유무만으로 `자료 제공·제출`을 선택하지 않습니다.
- “확인 부탁드립니다”라는 표현만으로 `검토·수정 요청`을 선택하지 않습니다.
- **검토할 대상과 회신·수정 요구가 구체적인지** 살핍니다.
- 특정 표기 정확성을 확인하고 답신을 요구한 **051**은 `검토·수정 요청`으로 해석했으나, 사실 정보 요청과의 경계는 추가 검증되지 않았습니다.

## 4. 판단 순서

1. **현재 행위와 요구를 먼저 적습니다.** 예: `견적서 제공`, `발행 정보 회신 요구`.
2. **전문 유형에 주제와 행위가 모두 맞는지 확인합니다.** 채용 관련 서류 제출을 단지 채용 관련이라는 이유로 `채용 문의`로 처리하지 않습니다.
3. **전문 유형이 맞지 않으면 공통 유형을 검토합니다.**
4. **복합 메일은 구체적인 자료·검토 결과·수정본 요구를 우선 검토합니다.** 안내나 제공과 함께 이런 요청이 있으면 요청 유형을 우선 검토합니다. 의무교육 이수 등 *모든* 행동 요구에 적용하는 규칙은 아닙니다.
5. **맞는 유형이 없거나 결정하기 어렵다면 보류**하고 이유를 기록합니다.

## 5. 보류 사유

| 보류 사유 | 뜻 |
| --- | --- |
| **범위 밖** | 현재 지원하는 업무 유형이 없음 |
| **맥락 부족** | 판단에 필요한 내용이 주어지지 않음 |
| **복합 의도** | 여러 주요 의도 간 우선순위가 불명확 |
| **기준 경합** | 둘 이상의 유형이 겹치며 정의만으로 구별하기 어려움 |

**보류는 업무 유형이 아니라 판정 상태**입니다.

## 6. 전문 유형의 적용 기록 — 확정 규칙이 아님

- **049:** 소프트웨어 라이선스 배정을 이용 권한 부여로 해석하여 `계정 생성/권한 요청` 선택.
- **044:** 장애 원인과 복구 조치가 명시되어 `시스템 오류 보고` 선택. 사후 보고서 제출과 공통 자료 제공·제출의 경계는 **미해결**로 남김.

이번 작업으로 전문 유형 26개를 전부 검증했다고 주장하지 않습니다.
