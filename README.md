# 업무 이메일 분류 체계 검증 및 기준 개선

> 작은 어긋남을 발견하고 더 나은 흐름을 만듭니다.

**개인 후속 프로젝트 · 문서/분류 기준 개선 · AI 생성 합성 이메일 52건**

졸업 프로젝트인 Gmail·Calendar 연동 이메일 AI 에이전트에서 기획했던 **7개 도메인·30개 업무 유형**을 실제 분류 상황에 적용했을 때도 일관되게 사용할 수 있을지 다시 검토했습니다. 합성 업무 이메일 52건을 직접 분류하고 일부 판단을 재검토하며, **현재 본문의 행위와 요청을 기준으로 읽는 판단 절차**, **공통 업무 유형 4개**, **보류 기준 4개**를 정리했습니다.

**핵심 결과:** `이메일 분류 가이드 v1.0` 문서화. 모델 정확도 향상이나 실제 서비스 성능 개선을 검증한 작업은 아닙니다.

## 왜 시작했나요?

기존 분류표는 사용자 온보딩과 답장 템플릿 선택을 위해 만들었습니다. 하지만 졸업 발표 과정에서 **답장으로 이어지는 메일은 어떻게 처리하는지** 질문을 받으면서, 제목·주제만 보고 업무 유형을 선택하면 실제 메일의 역할을 잘못 해석할 수 있다는 문제를 돌아봤습니다.

예를 들어 `견적서 발송드립니다`는 견적에 관한 메일이지만 **견적 요청**이 아니라 **자료 제공·제출**에 가깝습니다. ‘무엇에 관한 메일인가’와 ‘지금 무엇을 하고/요구하고 있는가’를 구별할 필요가 있었습니다.

## 발견 → 검토 → 개선

| 단계 | 이번 프로젝트에서 한 일 |
| --- | --- |
| **발견** | 요청과 회신 혼동, 여러 도메인에 걸친 공통 행위의 위치, 안내와 요구가 섞인 메일의 우선순위 문제를 발견 |
| **검토** | 합성 메일 52건을 읽고 판단·재검토 이유를 기록했으며, 보류할 사례와 미해결 경계를 구분 |
| **개선** | 전문 유형 26개를 유지하고 공통 유형 4개를 재구성하여 `v1.0` 판단 순서·포함/제외 기준·보류 절차 작성 |

### 대표 판단 변화

| 사례 | 이전 판단 | 최종 판단 | 왜 바꿨나요? |
| --- | --- | --- | --- |
| 002 | 견적 요청 | 자료 제공·제출 | 본문은 견적서를 **요청**하는 것이 아니라 **발송**하는 내용 |
| 003 | 공지 전달 | 검토·수정 요청 | 공지문 초안에 대한 **피드백**을 요구 |
| 041 | 협조 요청 | 보류 — 범위 밖 | 차량 키 **반납**은 자료 요청이 아닌 실물 처리 |
| 046 | 보류 — 복합 의도 | 자료 요청 | 일정 안내와 함께 **참석자 명단 제출**을 명시 |

더 자세한 사례는 [판단 사례 기록](docs/case-review.md)을 참고해 주세요.

## 정리한 분류 체계

| 구분 | 결과 |
| --- | --- |
| 원본 | 7개 도메인 · 30개 업무 유형 |
| 개선안 | **6개 전문 도메인 · 전문 유형 26개 + 공통 유형 4개 = 총 30개 유형** |
| 공통 유형 | 공지 전달 / 자료 요청 / 자료 제공·제출 / 검토·수정 요청 |
| 보류 사유 | 범위 밖 / 맥락 부족 / 복합 의도 / 기준 경합 |

**판단 순서:** 현재 본문의 행위 확인 → 주제와 행위가 모두 맞는 전문 유형 확인 → 공통 유형 검토 → 판단이 어려우면 보류 및 이유 기록

전체 분류표·포함/제외 기준은 [분류 가이드 v1.0](docs/classification-guide-v1.0.md)에 정리했습니다.

## 추가 6건 적용 기록

v0.5 기준 정리 후 새로운 합성 이메일 6건(047~052)을 먼저 분류하고 AI 검토 의견을 참고해 재검토했습니다. **048과 052, 총 2건의 최종 판단을 변경**했습니다. 이 숫자는 정답률이나 성능 개선률이 아니라 **판단 수정 건수**입니다.

## 작업 범위와 한계

- **모든 52건은 합성 이메일**이며 실제 업무 이메일을 대표하지 않습니다.
- **1인 판단 + AI 검토 의견**으로 진행했으며 독립 정답 라벨이나 작업자 간 일치도는 측정하지 않았습니다.
- 기준을 만든 사례를 다시 살펴본 결과이므로 **독립적인 전후 정확도 실험이 아닙니다**.
- 전문 26개 유형 전체를 재검증하지 않았고, 일부 경계는 해결하지 못했습니다.
- AI 모델 학습, 학습 데이터셋 구축, 답장 템플릿 품질 검증, 실제 서비스 수정 및 성능 평가는 **수행하지 않았습니다**.
